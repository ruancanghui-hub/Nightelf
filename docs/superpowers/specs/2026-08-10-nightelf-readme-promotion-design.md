# Nightelf README 推广设计

## 目标

把仓库首页改造成一页可信、易读、适合传播的产品介绍，让第一次访问的开发者能在一分钟内理解 Nightelf 的用途，愿意尝试源码构建，并通过 GitHub Star 表达支持。

## 目标读者

- 正在积累 Prompt、Skill、MCP 配置、AI 网站和 Workflow 的个人开发者
- 偏好本地文件、Git 和可迁移工作流的 AI 工具用户
- 想了解或参与 Flutter macOS 桌面项目的贡献者

## 核心叙事

首屏先回答三个问题：Nightelf 是什么、解决什么问题、为什么值得使用。核心表达为：

> 一个本地优先的 macOS AI 资源工作台，把散落的 Prompt、Skill、MCP、链接与 Workflow 收进由用户掌控的 Vault。

产品卖点按以下优先级呈现：

1. 本地优先，核心使用不要求账号或云服务。
2. 文件即真相，Vault 可由 Finder、编辑器和 Git 直接访问。
3. 多类 AI 资产在统一桌面界面中浏览、编辑和组织。
4. macOS 原生使用路径，包括目录恢复、Finder/终端入口和桌面网站悬浮球。

## 双语策略

README 采用同页双语，不复制两份完整长文。标题和关键定位使用中文与英文并列；操作说明以中文为主，并为核心段落提供精炼英文摘要。这样既保证中文读者的阅读连贯性，又让国际访问者能理解产品价值和启动方式。命令、文件结构与功能名称天然共用。

## 主视觉设计

主视觉必须来源于当前真实运行界面。优先选择能同时表现左侧资源导航、中间工作区与右侧信息区域的状态，并使用已有或临时示例 Vault 填充具有代表性的资源。

允许的后期处理：

- 裁切无关桌面区域，统一圆角与画布留白
- 添加低饱和深色或森林绿色背景、柔和阴影和轻微辉光
- 调整整体亮度、对比度和输出清晰度
- 添加简短、不遮挡界面的品牌标题

不允许的处理：

- 绘制应用中不存在的控件或数据能力
- 修改界面文案来暗示未实现功能
- 使用概念 UI 冒充真实产品截图

最终图片存放在仓库的 `docs/images/` 下，以适合 GitHub 展示的 PNG 输出；README 使用相对路径引用。若本机无法稳定运行应用，则使用仓库中已有的真实实现截图作为底图，并在交付说明中注明来源。
