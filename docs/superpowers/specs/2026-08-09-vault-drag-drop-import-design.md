# Vault 拖拽导入设计

## 目标

让用户把现有文件或文件夹直接拖入 AI 工作台，并在不修改原始内容的前提下，将副本安全、可审核地纳入本地 Vault。导入后的资源可被搜索、打开和 Git 同步，但拖入过程绝不执行任何脚本、MCP、Workflow 或网页。

## 范围与非目标

首版支持拖入单文件、多文件和文件夹，投放到整个工作台窗口、左侧具体资源分类或资源列表空白区域。

本功能不移动、删除或重命名源文件；不调用终端；不打开链接；不执行代码；不自动提交或推送 Git；不对二进制附件做内容解析或预览。

## 用户流程

1. 用户将一个或多个文件/文件夹拖到工作台。
2. 窗口显示蓝色高亮投放层，说明当前投放目标；投到具体分类时，该分类作为优先建议。
3. 应用扫描候选项的路径、扩展名和必要的轻量文本标记，生成导入审核面板。
4. 审核面板逐项显示来源、推荐资源类型、标题、目标名称、冲突处理和原因。用户可修改类型、标题与目标名称。
5. 用户确认后，应用将每个已选项复制到 Vault 的对应目录；源文件保持原样。
6. 每项复制成功后写入或更新资源元数据、刷新文件扫描和搜索索引、打开导入资源标签，并显示成功/失败结果。

用户可以从审核面板移除单个候选项或取消整个导入。取消和失败均不得留下半完成资源或临时文件。

## 类型建议与人工归类

识别只产生“建议”，最终类型始终由用户在审核面板确认。

| 候选输入 | 默认建议 | 复制目标 |
| --- | --- | --- |
| 含根级 `SKILL.md` 的文件夹 | SKILL 文件夹 | `skills/<目录名>/`，保留完整树结构 |
| `.json` 文件 | MCP 配置 | `mcp/<名称>.json` |
| `.mmd`、包含 Mermaid 代码块的 Markdown、Workflow YAML/JSON | Workflow 文件 | `workflows/` |
| `.url` 文件或纯 URL 文本 | 网站链接 | `links/<名称>.md` |
| `.md`、`.txt` | AI 提示词 | `prompts/<名称>.md` |
| 无法可靠识别的文件或文件夹 | 无预选类型 | 必须由用户选择五类资源之一 |

未被识别的输入绝不自动归类。若用户将普通文件归入某资源，应用按该资源的“附件/原始文件”规则复制，并在审核面板明确显示该文件不会被执行或解释为配置。

## 命名、冲突与原子性

导入前预览 Vault 内的目标路径。若同目录已有同名文件或文件夹，默认保留两份并为新副本自动追加序号，例如 `prompt.md` 变为 `prompt 2.md`。用户可在审核面板改名；不提供静默覆盖。

每个导入项使用“复制到同目录临时名称 → 校验复制结果 → 原子重命名”流程。多项导入以单项为边界：一项失败不会损坏已完成项，失败项显示可读原因与“重试”入口。取消或失败时清理该项临时文件。

导入结果仅在文件原子落盘后才更新资源记录、索引、最近使用和打开标签。目录导入保留内部目录结构；检测到软链接、不可读文件或循环目录时停止该候选项并解释原因，不跟随链接到 Vault 外部内容。

## UI 与无障碍

- 拖入窗口时显示 `释放以导入到工作台`；拖到具体分类时显示目标分类名称。
- 审核面板支持键盘焦点、逐项类型选择、重命名、移除、取消和确认；确认动作明确写为 `复制到 Vault`。
- 有冲突时显示原目标和自动生成的新名称；不会将“保留两份”误写成覆盖。
- 导入完成后用可访问状态消息报告成功数、失败数及可重试项。
- UI 首版支持深色/浅色与紧凑布局；大批量拖入使用可取消的进度摘要而非阻塞整个窗口。

## 架构与测试边界

引入独立于 Flutter 的 `ImportClassifier`、`ImportPlan` 和 `VaultImportRepository` 接口。平台拖拽适配层只将文件路径转为候选项；审核 UI 只编辑导入计划；仓储负责复制、原子提交、元数据与回滚清理。

测试使用临时 Vault 与临时源目录，覆盖：类型建议、未知类型必须人工选择、源文件未被修改、同名序号、SKILL 目录树保留、软链接拒绝、单项原子失败清理、取消、批量部分失败，以及导入后扫描/索引/标签刷新。Widget 测试覆盖投放层、审核面板和键盘操作。

## 与现有阶段的关系

此功能在 Vault 基础能力可创建、扫描和索引真实资源后实施：先建立分类与复制仓储接口，再在 Phase 2 的真实 Shell 中接入拖拽审核 UI。SKILL 文件夹导入复用并扩展原 Phase 3 的导入逻辑；不改变 Phase 5 的 Git 冲突审核原则。
